# CS Academic Portal — Tech Stack Report

> Generated by an automated exploration of the repository (August 2026).

## 1. Overview

A production-style, role-based academic portal for the Department of Computer Science at Dwaraka Doss Goverdhan Doss Vaishnav College (Chennai). It is a **client-heavy single-page application (SPA)** — React UI with a Firebase backend — plus a small set of **Vercel serverless functions** for PDF proxying/page-counting and a **Vite dev-middleware** equivalent for local development.

## 2. Frontend & Build Tooling

- **Vite 6** with the official **`@vitejs/plugin-react`**.
- A custom Vite plugin (`pdfPageCountPlugin` in `vite.config.js`) registers a **dev-only middleware** at `/api/pdf-page-count` that downloads a PDF (Google Drive or local `public/`) and returns its page count using **`pdfjs-dist`** (dynamically imported). In production this is served by the equivalent serverless function (see §5).
- Dev server runs on port `5173`; watch ignores PDFs and the `sem 1 english` folder.
- **No test framework** is configured (no unit/E2E tests anywhere in the repo).
- `npm run lint` → `eslint .` **fails**: ESLint 9 requires a flat config (`eslint.config.js`), and none exists.

## 3. Styling & UI System

- **Tailwind CSS 3.4** with a heavily customized `tailwind.config.js`:
  - **Colors**: maroon/rose `primary` (`#4A1620`), `secondary` (`#6B2332`), amber `accent` (`#D97706`), slate `dark` palette, `surface`, `muted`, `border`, `success/warning/error`.
  - **Font families**: configured as **`Fira Sans` / `Fira Code`** — ⚠️ *these fonts are never actually loaded* (see issues.md §Fonts). The real loaded fonts are **Inter + Outfit** (Google Fonts).
  - Custom shadows (`neu-raised`, `glass`, `premium`, `inner-glow` — all **teal-tinted** `rgba(13,148,136,…)` leftovers), border radius scale, backdrop-blur scale (`xs`…`glass-xl`), ~13 keyframe animations, and radial "mesh" backgrounds.
- **Global CSS** (`src/styles/index.css`):
  - CSS custom properties for **fluid typography & spacing** (`clamp()`-based: `--fluid-text-*`, `--fluid-container-*`, `--fluid-gap-*`, `--fluid-pad-*`, `--fluid-icon-*`).
  - A **neumorphic design system**: every `button` (unless `.no-neu`) gets a beveled box-shadow, amber hover glow, and `!important` amber border on hover.
  - Reusable component classes: `.glass`, `.glass-card(-hover)`, `.premium-card(-hover)`, `.btn-premium/primary/amber/ghost/outline`, `.input-premium(-error)`, `.badge-*`, `.card-grid`, `.stat-grid`, `.page-wrapper`, `.table-responsive` (⚠️ dead code — never used in any component), text-gradient utilities.
  - Global `min-height: 44px` touch-target rule for buttons/inputs.
- **Dark mode** via a `dark` class on `<html>` (`darkMode: "class"`), toggled by `ThemeContext` (persisted to `localStorage["csap-theme"]`).
- **Fonts loaded** (`index.html` + `@import` in `index.css`): Inter (400–900) and Outfit (500–900) from Google Fonts.

## 4. Backend — Firebase

Initialized in `src/firebase/config.js` from env vars (never hard-coded):

| Firebase service | Usage |
|------------------|-------|
| **Authentication** | Email/password login, register, forgot-password (role-based via Firestore `users` doc) |
| **Cloud Firestore** | Users, videos, notes, questionPapers, placements, notifications, CIA timetables, assignments, feedback, activity logs, `documentAI_uploads` |

- Security rules shipped: `firestore.rules`, `storage.rules`.
- Firestore collections (from README + code): `users`, `videos`, `notes`, `questionPapers`, `placements`, `notifications`.
- **Hard-coded admin bypass** in `ProtectedRoute.jsx`: `rollNumber === "24E3006" | "24E3013"` or `user.adminBadge` grants admin access regardless of role — a security note.

## 5. Serverless / Edge API (Vercel)

- `api/pdf-proxy.js` — Vercel serverless function that proxies a PDF (by Google Drive `id` or raw `url`) and streams it with CORS + caching headers (used to bypass Drive restrictions in the PDF viewer).
- `api/pdf-page-count.js` — production counterpart of the Vite dev middleware; returns `{ numPages }` for a PDF.
- `vercel.json` — SPA rewrites (`/(.*)` → `/index.html`) for client-side routing.
- **⚠️ Security/scale risk**: API keys for Groq (`VITE_GROQ_API_KEY`) are read **in the browser** (`groqService.js`) — the key is exposed to clients.

## 7. PDF, Documents & OCR

- Fluid `clamp()` sizing used extensively instead of fixed mobile breakpoints.

## 13. Notable Technical Risks

1. **Groq API key exposed in client bundle** — anyone can read it from the shipped JS.
2. **No ESLint config** — `npm run lint` is broken; no automated checks in CI.
3. **No tests** — zero unit/integration/E2E coverage.
4. **Huge single bundle (3.6 MB)** — slow initial load on mobile networks (a realistic audience for a college portal).
5. **Admin role bypass via hard-coded roll numbers** in `ProtectedRoute.jsx`.
6. Several **dead Tailwind utility classes** silently no-op (see `issues.md` §3) — verified against compiled CSS.
